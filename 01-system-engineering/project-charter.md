# Project Charter

## 1. Project Name

Connected Blood Pressure Monitor — Systems Engineering Prototype

## 2. Project Purpose

The purpose of this project is to design and prototype a connected blood pressure monitoring system as a hands-on Systems Engineering learning and portfolio project.

The project will demonstrate the application of Systems Engineering principles across the product lifecycle, from stakeholder needs and requirements through architecture, implementation, verification, validation, data and AI-enabled product capabilities.

## 3. Problem Statement

Blood pressure monitoring is commonly performed using standalone devices that provide a measurement but may offer limited integration with digital health workflows, longitudinal data analysis and intelligent insights.

This project explores how a connected blood pressure monitoring system could combine measurement hardware, embedded software, connectivity, data storage and analytics into an integrated system.

## 4. Project Objectives

### Primary Objectives

1. Develop practical Systems Engineering capability.
2. Apply concepts from the INCOSE Systems Engineering Handbook.
3. Prepare for the INCOSE Associate Systems Engineering Professional (ASEP) certification.
4. Design and prototype a connected BP monitoring system.
5. Develop practical experience in requirements, architecture, risk management and V&V.
6. Develop software and data capabilities.
7. Explore appropriate AI-enabled product features.
8. Document engineering decisions, trade-offs, failures and lessons learned.

## 5. System of Interest

The system of interest includes:

- Blood pressure cuff
- Pneumatic subsystem
- Pressure sensing
- Embedded controller
- Firmware
- Connectivity
- Application interface
- Data storage
- Analytics
- AI-enabled insights

The system boundary will be refined during the Systems Engineering process.

## 6. Key Stakeholders

Initial stakeholders include:

- End user / patient
- Caregiver
- Healthcare professional
- Product owner
- Systems engineer
- Software engineer
- Quality engineer
- Regulatory stakeholders
- Manufacturer
- Service/support organization

Stakeholder needs will be investigated and refined during the project.

## 7. Project Scope

### In Scope

- System definition
- Stakeholder analysis
- User needs
- System requirements
- System architecture
- Hardware component selection
- Embedded software
- Connectivity
- Data management
- Risk analysis
- Verification strategy
- Prototype testing
- Product requirements
- AI feature exploration

### Out of Scope

- Clinical validation
- Commercial medical-device certification
- Regulatory submission
- Use of the prototype for diagnosis or treatment
- Production manufacturing
- Clinical decision-making

## 8. Key Constraints

- Personal learning project
- Limited development budget
- Prototype-grade hardware
- Limited development time
- No access to clinical testing infrastructure
- Safety must take priority over experimentation

## 9. Success Criteria

The project will be considered successful when it demonstrates:

1. A documented system architecture.
2. A defined set of stakeholder and user needs.
3. A structured system requirements baseline.
4. Requirements traceability.
5. Preliminary risk analysis.
6. A working engineering prototype.
7. Defined verification activities.
8. Documented test results.
9. Software implementation and testing.
10. A documented product strategy.
11. An evaluated AI-enabled feature.
12. A complete record of engineering decisions and lessons learned.

## 10. Engineering Principles

The project will follow these principles:

- User needs before technology
- Requirements before implementation
- Safety before functionality
- Evidence before assumptions
- Verification of requirements
- Validation of intended use
- Explicit engineering trade-offs
- Documented decisions
- Iterative development
- Continuous learning

## 11. Reference Frameworks

The project will study and apply relevant concepts from:

- INCOSE Systems Engineering Handbook
- ISO 14971
- IEC 62304
- IEC 62366
- ISO 13485
- Applicable FDA and EU medical-device concepts

The applicability of each standard will be evaluated rather than assumed.

This project is an educational engineering prototype and is not a clinically validated medical device.

It must not be used for medical diagnosis, treatment or clinical decision-making.
